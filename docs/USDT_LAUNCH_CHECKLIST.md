# USDT-платежи — чеклист перед запуском

Один раз пройти ручками перед открытием игры реальным игрокам.
Гарантирует что **деньги не пропадут** и алмазы придут **ровно один раз**.

Все 3 пути доставки уже покрыты автотестами (`make test-payments`),
но надо ещё проверить «трубы» вокруг — настройки CryptoPay, env-переменные,
доступность webhook-endpoint снаружи.

---

## ПОДГОТОВКА (10 минут)

### 1. Получить боевой токен CryptoPay

- [ ] Зайти в https://t.me/CryptoBot → меню «Crypto Pay» → «Create App»
- [ ] Создать приложение (можно «Duel Arena Prod»)
- [ ] Скопировать **API Token** (выглядит как `12345:AA...длинная_строка`)

> Сейчас в коде по умолчанию стоит **тестовый** токен (testnet). Это удобно для тестов 1-3 ниже — можно платить «фейковые» USDT без потерь. Боевой токен подключаем только перед финальным шагом.

### 2. Настроить env-переменные на проде

В `.env` на сервере:
```
CRYPTOPAY_TOKEN=ТВОЙ_БОЕВОЙ_ТОКЕН
CRYPTOPAY_TESTNET=0
```

- [ ] Файл `.env` есть на сервере и содержит обе переменные
- [ ] `.env` есть в `.gitignore` (чтобы токен не утёк в git)
- [ ] Перезапустить бота, чтобы переменные подхватились

### 3. Зарегистрировать webhook URL в CryptoPay

В https://t.me/CryptoBot → твоё App → Webhooks → Add:

```
https://ТВОЙ_ДОМЕН/api/webhooks/cryptopay
```

- [ ] URL добавлен
- [ ] Сервер отвечает на этот URL (проверка: `curl https://ТВОЙ_ДОМЕН/api/webhooks/cryptopay -X POST` → должен ответить 400 или 401, **не 404**. 404 = endpoint не зарегистрирован)
- [ ] HTTPS работает (без HTTPS CryptoPay не пошлёт webhook)

---

## ТЕСТ 1 — Webhook (основной путь, ~5 минут)

Проверяем что нормальный сценарий работает.

### Что делаем:
- [ ] Открыть мини-апп со своего телефона
- [ ] Зайти в магазин → купить пакет **«100 алмазов за 2.99 USDT»**
- [ ] CryptoPay покажет QR — оплатить через @CryptoBot (тестовый USDT)
- [ ] **В течение 30 секунд** в логах сервера должно появиться:
  ```
  CryptoPay paid: uid=ТВОЙ_ID diamonds=100 ...
  ```
- [ ] В мини-аппе всплыло «💎 +100 алмазов»
- [ ] Профиль показывает +100 алмазов

### Если что-то пошло не так:
- **Логи пусты:** webhook не дошёл. Проверь что URL открыт снаружи (`curl` из другого места).
- **«invalid signature» в логах:** токен в `.env` не совпадает с тем, что в CryptoPay-панели.
- **Алмазы не пришли:** смотри ошибку в логах (`grep CRITICAL` или `grep equip failed`).

---

## ТЕСТ 2 — Polling (резервный путь от мини-аппа)

Проверяем что мини-апп сам подтянет платёж, если webhook сломался.

### Подготовка:
- [ ] Временно **отключить webhook** в CryptoPay-панели (или поставить заведомо неверный URL)

### Что делаем:
- [ ] Купить пакет **«100 алмазов за 2.99 USDT»** ещё раз
- [ ] Оплатить через CryptoBot
- [ ] **В логах НЕ должно быть** строки `CryptoPay paid:` через webhook
- [ ] В течение ~30 секунд мини-апп сам должен опросить и зачислить алмазы
- [ ] В логах появилась строка про `crypto_check` или зачисление через polling
- [ ] Профиль показывает +100 алмазов

### После теста:
- [ ] **Вернуть webhook URL обратно** в CryptoPay-панели (иначе путь 1 будет сломан в проде!)

---

## ТЕСТ 3 — Ручное восстановление (если оба пути упали)

Проверяем что админ сможет «вытащить» застрявший платёж.

### Подготовка:
- [ ] Снова отключить webhook в CryptoPay-панели
- [ ] Закрыть мини-апп **сразу после оплаты** (чтобы polling не сработал)

### Что делаем:
- [ ] Купить пакет **«100 алмазов за 2.99 USDT»**
- [ ] Оплатить через CryptoBot
- [ ] Закрыть мини-апп
- [ ] Подождать 1 минуту
- [ ] В Telegram-боте написать: `/my_lost`
- [ ] Бот покажет твой неполученный платёж
- [ ] Написать: `/recover_all_my`
- [ ] Бот ответит «восстановлено N платежей»
- [ ] Профиль показывает +100 алмазов

### После теста:
- [ ] Вернуть webhook URL обратно

---

## ТЕСТ 4 — Защита от «двойного начисления»

Проверяем главный гарант: даже если webhook + polling + recover сработают одновременно — алмазы зачислятся **ровно один раз**.

### Что делаем:
- [ ] Купить пакет, оплатить
- [ ] Дождаться зачисления через webhook (логи показали)
- [ ] Сразу после этого открыть мини-апп → нажать «Проверить» (если есть кнопка) → polling вызовется
- [ ] Сразу после этого выполнить `/recover_all_my` в боте
- [ ] **Алмазы должны вырасти ровно на пакет (например 100), НЕ 200 и НЕ 300**

> Этот сценарий уже покрыт автотестом `test_three_delivery_paths_idempotent` — но один раз вживую полезно убедиться.

## ФИНАЛ — Реальный платёж 0.5 USDT (после переключения на боевой токен)

### Подготовка:
- [ ] В `.env` стоит **боевой** `CRYPTOPAY_TOKEN` (не testnet)
- [ ] `CRYPTOPAY_TESTNET=0`
- [ ] Сервер перезапущен
- [ ] Webhook URL в боевой CryptoPay-панели зарегистрирован

### Что делаем:
- [ ] Купить **самый дешёвый пакет** (минимум $2.99 — это ~3 USDT, но реальные)
- [ ] Оплатить из своего личного кошелька CryptoBot
- [ ] Webhook пришёл → алмазы на счету
- [ ] Эти 3 USDT теперь у проекта на CryptoPay-балансе — можно вывести обратно через @CryptoBot

> Если жалко 3$ — можно после запуска купить себе самому, как первый игрок. Деньги останутся «у тебя».

---

## ОТКАТ если что-то пошло не так

Если после переключения на боевой токен что-то сломалось:
- [ ] Вернуть в `.env`: `CRYPTOPAY_TESTNET=1` и старый тестовый токен
- [ ] Перезапустить бота
- [ ] Проверить через тест 1 что снова работает на testnet
- [ ] Разобраться с боевым токеном без давления

---

## КУДА СМОТРЕТЬ В ЛОГАХ

| Что искать | Что значит |
|---|---|
| `CryptoPay paid: uid=` | webhook принят, алмазы зачислены |
| `invalid signature` | токен в .env не тот |
| `CRITICAL: ... equip failed` | webhook принят, но выдача предмета упала |
| `recovered invoice=` | сработало ручное восстановление |
| `crypto_check` | сработал polling от мини-аппа |

Удобный grep на сервере:
```bash
tail -f bot.log | grep -i 'cryptopay\|invoice\|recovered'
```
