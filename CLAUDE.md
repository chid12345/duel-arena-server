## Регламент для ИИ — Duel Arena Server

Короткий, без воды. Это **единственный** регламент, который читается всегда.
Детали и справка — в `docs/*` (читать только по теме задачи). **Старт:** `docs/INDEX.md` — выбрать блок по ключевым словам, не «всё подряд».

## Роль ИИ
- ИИ = геймдизайн + архитектура + качество.
- Любая идея → “пакет решения”: **зачем игроку / баланс / активность / прогресс**. Если 2+ пункта пустые — не делаем или упрощаем.

## Законы проекта (обязательны)

### Закон 1. Лимит размера файла (200 / 300)
- **Норма**: до **200** строк.
- **Если файл > 200 (обычно 200–250)**: новую логику **не добавляем** — начинаем новый модуль или делим файл.
- **Аварийный порог**: **300** строк → **сразу** распил и только потом новые фичи.
- **Исключений по размеру нет**; монолиты — только пакеты (`db_schema/`, `battle_system/`) с модулями ≤200 строк.

### Закон 2. Структура “Лего” (новый дом)
- Новая тема/механика/контент → **сразу отдельный модуль** (файл/папка).
- Если файл раздувается по смыслам → “Матрёшка” (папка). Если раздувается из‑за списка контента/умений → “Библиотека умений”.

### Закон 3. Импорты без циклов
Разрешённая цепочка:
`config/progression_loader → db_core → db_schema → repositories → database → battle_system → handlers/api_server`.
Запрещены импорты “вверх по цепочке”. Если надо “кверх” — передаём параметром.

### Закон 4. Минимальный контекст (правило 3 файлов)
Начинаем с **1–3 файлов** по теме задачи. Расширяем только если не хватает данных.

### Закон 5. Отчёт после работы (1 строка)
`Готово: <что сделано>. version.py X→Y, GAME_VERSION A→B. Запушено.`

### Закон 6. Безопасный распил (чеклист)
- План распила (3–5 строк).
- Сначала перенос (без изменения логики), потом улучшения.
- Импорты привести к Закону 3.
- Smoke-тест: `python -c "from database import db; from handlers import BotHandlers"`.
- Проект рабочий сразу, без “доделаем потом”.

### Закон 7. Коротко и по делу
Меняем **только нужное** для задачи. Не пишем простыни, не делаем косметику без причины.

### Закон 8. Нет мёртвого кода
Не оставляем “старое” закомментированным “про запас”. Если не используется — удаляем (или сначала проверяем использования).

### Закон 9. Новая категория → новый дом
Новая категория контента/системы → отдельный модуль. Не “подселять” в чужой файл.

### Закон 10. Версии + коммит + пуш (после каждой правки кода)
После **каждой** правки кода:
- поднять `version.py`
- поднять `GAME_VERSION` на **+0.01**
- `git commit`
- `git push`

### Закон 11. Тесты живут вместе с кодом (без напоминаний)
Любая правка в `repositories/`, `battle_system/`, `economy/`, `api/`, `handlers/` ИДЁТ В ПАРЕ с правкой `tests/`. ИИ обязан делать это сам, не дожидаясь просьбы.

**🆕 НОВОЕ → НОВЫЙ ТЕСТ (всегда):**
- Любая новая функция/фича/механика → дописать **2-5 тестов** в `tests/` в **той же правке**.
- Минимум: 1 тест «happy path» (как должно работать) + 1-2 граничных (что-то идёт не так).
- Примеры: новый квест → тест на claim; новый предмет → тест на покупку; новая команда → тест на её действие; новая формула → тест на ключевые числа.
- Без теста — фича считается **недоделанной**, в commit не идёт.

**🔧 ИЗМЕНЕНИЕ → ОБНОВЛЕНИЕ ТЕСТА:**
- `grep -r "имя_функции" tests/` перед правкой — есть ли тесты на это место.
- Меняешь число/формулу/логику → обнови ассерты в той же правке. Пример: зелье 12→6g → в `test_shop_buys.py` ассерт `cost == 60` тоже обновить.

**🗑️ УДАЛЕНИЕ → УДАЛЕНИЕ ТЕСТА:**
- Удаляешь функцию → удали её тесты (не оставляй красное «потом починим»).

**✅ ПРОВЕРКА:** `python -m pytest tests/ -v` перед коммитом → должно быть **зелёным**.

**❌ ЗАПРЕЩЕНО:** оставлять красные тесты в коммите. Привычка «игнорить красное» = убийство всей системы за месяц.

### Закон 12. Справка живёт вместе с кодом
Игровая справка для пользователя — `webapp/scene_guide_data*.js` (4 файла). Если правка кода меняет что-то, что **видит игрок** (цифры, цены, шаги, названия кнопок), карточка в справке правится **в той же правке**. Иначе игрок откроет «Справка» и прочтёт враньё.

**Карта «правишь Х → проверь Y»:**
| Что меняешь в коде | Где смотреть в справке |
|---|---|
| `config/battle_constants.py` (зоны, крит, уклон, броня, таймер) | `scene_guide_data.js` — Бой, Статы |
| `battle_system/`, `config/progression_*` | `scene_guide_data.js` — Бой, Статы |
| `repositories/equipment/`, `config/sets_catalog_v2.py` | `scene_guide_data.js` — Снаряга |
| `api/shop_*.py`, `economy/`, `api/shop_loot_box.py` (цены, ящики, зелья, свитки) | `scene_guide_data2.js` — Магазин |
| `config/avatar_catalog.py` (категории, цены, бонусы образов) | `scene_guide_data2.js` — Образы |
| `repositories/social/clans*.py`, `clan_bonus.py` | `scene_guide_data4.js` — Социал (клан) |
| `config/world_boss/`, `repositories/world_boss/` | `scene_guide_data4.js` — Социал (босс) |
| `repositories/social/referrals_*` (шкала %, минимум вывода, кулдаун) | `scene_guide_data4.js` — Социал (рефералы) |
| `repositories/quests/`, `definitions_tasks.py`, `tma_weekly_quests.py` | `scene_guide_data3.js` — Задания |
| `repositories/users/premium.py`, `economy/premium_bonus.py`, `wipe_leaderboard.py` | `scene_guide_data3.js` — VIP |
| Новая вкладка в магазине / новый экран в меню — добавь карточку «как зайти, что увидишь, что нажать» | соответствующий `scene_guide_data*.js` |

**Проверка перед коммитом:**
1. Открой соответствующий `scene_guide_data*.js`, найди карточку (Ctrl+F по теме).
2. Сверь цифры/тексты в `detail` с тем, что в коде. Расходится → обнови.
3. Новая фича → добавь карточку (icon, title, desc, detail, where).
4. Удалил фичу → удали карточку.

**❌ Запрещено:** оставлять в справке устаревшие цифры/инструкции. «Игрок прочтёт неправду» = убийство доверия за неделю.

## Где лежат подробности (9 блоков + навигатор)
- Навигатор по ключевым словам → `docs/INDEX.md`
- Архитектура/карта/куда класть/SQL/Mixin → `docs/ARCHITECTURE.md`
- Бой/лог боя/правила изменений → `docs/BATTLE.md`
- Экономика/баланс/синки → `docs/ECONOMY.md`
- Магазин/предметы/зелья → `docs/SHOP.md`
- UX/тексты/кнопки → `docs/UX_TEXTS.md`
- Квесты/ежедневки/ивенты (старые) → `docs/QUESTS.md`
- Система заданий v2/стрик/достижения → `docs/TASKS.md`
- Кланы/соц/рефералы/платежи → `docs/SOCIAL.md`
- Мировой босс/рейды/WS-бродкаст/свитки рейда → `docs/WORLD_BOSS.md`
